# check_llm_access

Bash-скрипт, который проверяет, доступны ли API основных LLM-провайдеров с текущего сервера. Он обращается к эндпоинтам **без API-ключей** и по ответу отличает «доступно» от гео-блокировки и сетевых проблем. Если задать ключи в переменных окружения, скрипт делает настоящие минимальные запросы и проверяет гео-ограничения так, как их видит сам провайдер.

- 25 провайдеров в одном запуске
- проверка гео-ограничений с ключом или по списку стран
- параллельные проверки
- поддержка HTTP- и SOCKS-прокси
- код возврата для cron и CI
- нужен только `bash` и `curl`

## Быстрый старт

```bash
chmod +x check_llm_access.sh
./check_llm_access.sh                          # обычная проверка
./check_llm_access.sh -v                       # + фрагмент тела ответа
./check_llm_access.sh -p socks5h://host:1080   # через прокси
GEMINI_API_KEY=... ./check_llm_access.sh       # точная проверка Gemini с ключом
```

## Параметры

| Флаг     | Описание                                                    | По умолчанию |
|----------|-------------------------------------------------------------|:------------:|
| `-t SEC` | Таймаут на один запрос                                      | `10`         |
| `-j N`   | Число параллельных проверок                                 | `8`          |
| `-p URL` | Прокси: `http://host:port` или `socks5h://host:port`        | —            |
| `-c CC`  | Код страны для сверки со списком неподдерживаемых стран     | из ipinfo.io |
| `-v`     | Показывать фрагмент тела ответа                             | выкл.        |
| `-n`     | Не определять внешний IP и страну (не обращаться к ipinfo.io) | выкл.      |
| `-h`     | Справка                                                     |              |

## Как это работает

Скрипт отправляет запрос без ключа на каждый эндпоинт. Ответ `401` или `403` «нужен ключ» означает, что сеть и регион в порядке: сервер принял соединение и просто просит авторизацию. Гео-блокировка определяется по коду и тексту ответа.

Однако не все провайдеры проверяют страну до ключа. OpenAI и Anthropic отказывают сразу, а Gemini сначала проверяет ключ и только потом страну. Без ключа запрос к нему из России выглядит успешным, хотя настоящий запрос вернёт `400 User location is not supported`. Для таких случаев есть два механизма.

### Проверка с ключом

Если ключ задан в переменной окружения, скрипт отправляет настоящий запрос, и его результат окончательный. Ключ передаётся curl через stdin и не виден в списке процессов.

| Провайдер | Переменная                          | Запрос                                         |
|-----------|-------------------------------------|------------------------------------------------|
| OpenAI    | `OPENAI_API_KEY`                    | `GET /v1/models`                               |
| Anthropic | `ANTHROPIC_API_KEY`                 | `GET /v1/models`                               |
| Gemini    | `GEMINI_API_KEY` или `GOOGLE_API_KEY` | `generateContent`, 1 токен (модель — `GEMINI_MODEL`, по умолчанию `gemini-flash-latest`) |
| Mistral   | `MISTRAL_API_KEY`                   | `GET /v1/models`                               |
| Cohere    | `COHERE_API_KEY`                    | `GET /v1/models`                               |
| xAI       | `XAI_API_KEY`                       | `GET /v1/models`                               |
| DeepSeek  | `DEEPSEEK_API_KEY`                  | `GET /models`                                  |
| Groq      | `GROQ_API_KEY`                      | `GET /openai/v1/models`                        |

Для Gemini нужен именно `generateContent`: на `/models` гео-фильтр не срабатывает. Такой запрос стоит доли цента. Если ключ недействителен, скрипт выдаёт `WARN` с пометкой «страна не проверена».

### Сверка со списком стран

Если ключа нет, а сервер ответил, страна сервера сверяется с массивом `UNSUPPORTED` в начале скрипта. Если страна там есть, вместо `OK` выводится `GEO?`. Страна берётся из ipinfo.io или задаётся вручную через `-c` (пригодится вместе с `-n`).

Списки приблизительные. Кроме того, GeoIP провайдера может определить страну иначе, чем ipinfo.io, поэтому для окончательного ответа нужен ключ.

### Статусы

| Статус  | Значение                                                                                                         |
|---------|------------------------------------------------------------------------------------------------------------------|
| 🟢 `OK`    | Сервер ответил, регион разрешён                                                                               |
| 🔴 `GEO`   | Гео-блокировка: «User location is not supported» у Gemini, `unsupported_country_region_territory` у OpenAI, HTTP 451 |
| 🔴 `GEO?`  | Сервер отвечает без ключа, но страна сервера в списке неподдерживаемых — без ключа не подтвердить               |
| 🔴 `BLOCK` | `403` без признаков запроса авторизации — похоже на блокировку по IP или региону (так отвечает, например, Anthropic) |
| 🔴 `FAIL`  | Сетевая ошибка: DNS, таймаут, сброс соединения, ошибка TLS                                                    |
| 🟡 `WARN`  | `5xx`, нестандартный ответ или отклонённый ключ                                                                              |

Перед таблицей результатов скрипт показывает внешний IP, страну и провайдера сервера (через [ipinfo.io](https://ipinfo.io), отключается флагом `-n`).

### Коды возврата

| Код | Значение                                         |
|:---:|--------------------------------------------------|
| `0` | Все провайдеры доступны (допускаются `WARN`)     |
| `1` | Есть `FAIL`, `GEO`, `GEO?` или `BLOCK`           |
| `2` | Ошибка запуска (нет `curl`, неверный флаг)       |

### Как добавить провайдера

Эндпоинты лежат в массиве `ENDPOINTS` в начале скрипта. Добавьте строку в формате `"Имя|URL"` или `"Имя|URL|id"`:

```bash
ENDPOINTS=(
  ...
  "My Provider|https://api.example.com/v1/models"
)
```

Лучше выбирать URL, который без ключа возвращает `401`/`403`/`404` и не требует тела запроса (обычно это `/v1/models`).

Необязательный `id` связывает провайдера со списком стран в `UNSUPPORTED` и с проверкой по ключу в функции `key_probe`.

Паттерны гео-блокировок задаются в переменной `GEO_RE` — туда можно дописать новый текст ошибки, если какой-то провайдер отвечает по-своему.
